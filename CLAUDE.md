# Working rules for this repo

The person working here is redesigning this app and wants to
own the code, not just receive it.

Before writing any code:
1. Explain WHAT you're about to change (which files, which lines).
2. Explain WHY — what problem it solves, what alternatives exist.
3. Wait for confirmation. Do not change files in the same reply
   as the explanation.

While working:
- One file per step. Never touch multiple files in a single change
  unless explicitly asked.
- No large rewrites. Show a small diff, not a replaced file.
- After each change, state WHAT IF: what would break if this
  change were reverted or done differently.
- If I ask for something that seems wrong, say so instead of
  complying quietly.

Explanation style: simple English or Hinglish, no jargon without
unpacking it. Assume I will have to explain this code to someone
else later.
